## 放在哪、怎么推

仓库推在 **B2 机器**（`pyaissh @b2`）上，因为那台有 `gh` 且已登录。
本地工作目录只留这份说明，源码不在本地。

以后要更新远端：

```bash
# 1. 本地打包（代码本体就在 tools/xhh-mcp，直接打）
cd /root/工作目录/AIlife && tar czf /tmp/xhh-repo.tgz tools/xhh-mcp
# 顺手把文档也带上
mkdir -p /tmp/xhh-docs && cp docs/小黑盒*.md /tmp/xhh-docs/

# 2. 传到 B2
python3 /root/.dsh/skills/pyaissh/pyaissh.py upload @b2 --local /tmp/xhh-repo.tgz --remote /tmp/xhh-repo.tgz
python3 /root/.dsh/skills/pyaissh/pyaissh.py upload @b2 --local /tmp/xhh-docs --remote /tmp/xhh-docs

# 3. 在 B2 上重新 clone（临时目录用完即删，不留残留）、覆盖、推
python3 /root/.dsh/skills/pyaissh/pyaissh.py exec @b2 --cmd '
  cd /tmp && rm -rf xhh-clone && gh repo clone huajiao1998/xiaoheihe-mcp xhh-clone &&
  cd xhh-clone && find . -mindepth 1 -maxdepth 1 ! -name .git -exec rm -rf {} + &&
  tar xzf /tmp/xhh-repo.tgz --strip-components=1 -C . &&
  cp -r /tmp/xhh-docs/. docs/ &&
  git add -A && git commit -m "更新：<改了什么>" && git push --force-with-lease &&
  cd /tmp && rm -rf xhh-clone xhh-repo.tgz xhh-docs'
```

> 为什么每次重新 clone：B2 上不留常驻副本，用完就删，免得下次忘了哪个是新的。

## 2026-10-27 21:55 改成「工具本体」

老板问：「我们现在的工具是补丁形式吗，能不能去掉补丁形式，直接做进工具本体」。

### 先说清楚：之前也不是"补丁"

代码一直是直接写在 `service.py` / `mcp_server.py` 里的，不是什么 monkey patch 或运行时钩子。
**问题不在"补丁"，在"住在谁家"**——它住在 uv tool 的 `site-packages` 里，
那是别人包的地盘，重装/换机器/清缓存都可能被冲掉。

老板说「不存在升级的问题」，这话对了一半：我们确实不跟上游升级了。但**重装**是另一回事，
跟版本无关。

### 做法：editable 安装

```bash
# 把代码搬进项目
tools/xhh-mcp/
├── pyproject.toml      # 声明包（版本 0.1.0+local.1）
├── install.sh          # 装 / 重装
├── xhh_operator/       # 改过的完整源码
├── xiaoheihe/
└── *.py                # 上游 10 个模块

# 装进去
uv tool install --editable tools/xhh-mcp --force
```

装完 `site-packages` 里没有代码副本了，只剩两个指针：

```
__editable__.xiaoheihe_cli-0.1.0+local.1.pth
__editable___xiaoheihe_cli_0_1_0_local_1_finder.py
```

**改项目里的文件 → 重启 MCP → 立刻生效**，不用重装。

### 顺手补记一处之前漏掉的改动

`xhh_operator/http.py`：原版把所有上游失败压成一句「小黑盒拒绝了操作，请检查账号权限、内容及接口兼容性」，
看不到真正原因。改成把上游 `msg` 透出来（超 300 字截断）。

**这条价值极大**——关注接口靠它吐出的「both following id and follower id is required」
才挖到参数名。原版那句话会把线索吞掉。

### 现在重装只要一条命令

```bash
bash tools/xhh-mcp/install.sh
```

脚本会断言加载路径指向项目目录（防止静默装成别的），并检查四个关注工具在不在。
