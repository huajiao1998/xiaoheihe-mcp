# 小黑盒私信与好友：能做什么、不能做什么

> 2026-10-27 查证，结论写清楚，省得以后又从头试一遍。

## 结论先说

| 想要 | 能不能 | 怎么做到的 |
|---|---|---|
| 收到私信 | ✅ 能（读得到正文） | `list_messages(kind="official")`，里面 `entry=message` 的那几行 |
| 发出私信 | ❌ 不能 | 网页 API 没有发送接口，私聊只有 App 端 |
| 看到好友申请 | ✅ 能 | 同上，`sub_entry=heychat` 的那几行 |
| 通过/拒绝好友 | ❌ 不能 | 接口不存在 |
| 关注通知 | ✅ 能 | `list_type=2` 的 header 里有 `entry=follow` |

## 查证过程（别再重复试这些）

能用的接口：

- `/bbs/app/user/message?list_type=0|1|2` —— 消息中心。0=评论回复，1=赞，2=通知（**私信和好友申请就混在 2 里**）
- `/bbs/app/user/message/detail?list_type=...` —— 带 `header`，列出全部消息分类：comment / award / follow / at。**没有私信分类**
- `/bbs/app/message/list` —— 系统通知，不是私聊

试过但 404 的（别再试）：

```
/bbs/app/chat/session/list
/bbs/app/chat/list
/bbs/app/user/chat/list
/bbs/app/heychat/session/list
/bbs/app/heychat/message/list
/bbs/app/heychat/chat/list
/bbs/app/heychat/conversation/list
/bbs/app/message/chat
/bbs/app/message/history
/bbs/app/message/detail
/bbs/app/user/friend/list
/bbs/app/profile/user/friend/list
/bbs/app/heychat
```

试过但报「无效的message_type」的：

```
/bbs/app/user/message/heychat?list_type=3..12
```

这个路径存在，但只认 list_type=1（赞）和 2（header），本质是通用消息接口，不是私信专用。

## 私信数据长什么样

`list_type=2` 的那条私信原始字段：

```json
{"entry": "message",
 "message_id": 17427849,        // ← 就是对方 uid
 "text": "小鱼鱼能收到私信吗",
 "timestamp": 1793106261,
 "user_a": {"username": "一品先生", "userid": 17427849, ...}}
```

好友申请那条：

```json
{"entry": "official_msg_v2",
 "sub_entry": "heychat",
 "text": "一品先生 申请加为好友",
 "protocol": "heybox://{... \"path\":\"/flutter/voice_message_box\", \"params\":{\"type\":\"chat_request\"} ...}"}
```

`protocol` 里指的是 App 内的 Flutter 页面——**私信和好友功能在网页版没有对应路由**，`www.xiaoheihe.cn/message` 打开是 30 字节的空壳。

## 改了什么

`xhh_operator/service.py` 的 `messages(kind="official")`：原来把所有条目一视同仁只念 `text`，现在按 `entry`/`sub_entry` 分开——

- `entry=message` → 标成「私信」，带对方 uid
- `sub_entry=heychat` → 标成「好友申请」
- 其余 → 官方通知

改完必须 `kill <xiaoheihe-cli mcp 的 pid>`，让 dsh 重启 MCP 才生效。

### 网页版为什么打不开

`www.xiaoheihe.cn` 是个 SPA，浏览器一进去就报
`TypeError: Cannot read properties of null (reading 'nextSibling')`，挂载直接失败，页面渲染不出来。
不是登录态的问题（cookie 是注入过的），是它这套前端在无头浏览器里跑不起来。
`/message` 路由也是空壳，30 字节。

### 读私信的真相

`/bbs/app/user/message?list_type=2` 里 `entry=message` 那条**是会话摘要，不是消息本身**：

```json
{"entry": "message", "message_id": 17427849, "count": 2, "text": "小鱼鱼", ...}
```

`count` 是未读条数，`text` 只有**最后一条**。所以第二次发私信会把前一条顶掉——
2026-10-27 晚上先后发的「小鱼鱼能收到私信吗」和「小鱼鱼」，只读得到后面那句。

好友申请的 `protocol` 字段也露了底：

```
heybox://{"path":"/flutter/voice_message_box","params":{"type":"chat_request"},"protocol_type":"openRouterPath"}
```

私信和好友都是 **Flutter 页面 + 长连接**，REST 这边只给会话摘要，本来就不打算让网页端读全量。

## 补三：逆向帖子看完了，技术原因也清楚了（2026-10-27 21:40）

老板给了 [某黑盒 App 登录参数逆向分析](https://nshide1.github.io/2025/11/03/%E6%9F%90%E9%BB%91%E7%9B%92%20App%20%E7%99%BB%E5%BD%95%E5%8F%82%E6%95%B0%E9%80%86%E5%90%91%E5%88%86%E6%9E%90/)。
它讲的是登录 `nonce` 怎么逆，不是私信，但从里面能推出几件硬事实：

1. **App 端的请求保护在 native 层 + VM**。`nonce` 由 `libhbsecurity.so` 的 `getVX`/`getVD` 生成，
   最新版还套了虚拟机保护，要 Frida + sktrace trace 才追得下去。网页端算的那套 `hkey` 跟它不是一回事。
2. **`/chat/` 是独立服务**。它的返回长这样：`{"status":"failed","msg":"...","version":"1.0","result":{}}`，
   而 `/bbs/app/` 是 `{"status":"ok","result":{...}}`。**两套完全不同的后端**。
3. **hkey 校验在业务参数之前**。把签名挪到请求头，它立刻说「hkey 不能为空」；
   签名放回查询参数，就变成「参数错误」。**说明签名这关一直是对的，卡的是业务参数。**
4. **JSON body 不行**。试了 `json={"to_userid":...,"text":...}`，照样「参数错误」；
   header 签名 + JSON、header 签名 + form 也都是「hkey 不能为空」或「参数错误」。
5. **传垃圾值也不吐细节**。`userid=abc`、`text` 五千字、只传 text —— 四种全是「参数错误」，
   不像关注接口那样会说缺哪个字段。

顺带搜到的 [xhhBackCrack](https://github.com/luckylca/xhhBackCrack) 是网页端 13 个接口的合集
（feeds / user_profile / link_tree / comment_list / user_news / recommend_user / hot_topics /
game_list / user_posts / notifications / search_found / data_report / emojis_list），
**也没有私信**。

### 结论（这次是真的结论）

网页端能碰到的接口，全网公开资料里就这些。私信要么在 App 独有路径上、参数由 native 层校验，
要么干脆是长连接协议。**网页 cookie 这条路到顶了。**

想再往下只有两条：
- 真机 + Frida + ROOT，trace `libhbsecurity.so` —— 这台 4G 无 GPU 的服务器做不到；
- 老板抓一次包，把「发私信」那条请求的完整 URL + 表单/JSON 体贴过来。

**除此之外不再试了。** 评论区够用。

## 补四：关注功能通了，之前的「接口坏了」是我自己写错（2026-10-27 21:45）

一直显示 0 条，我先后判断成「限流」「接口坏了」「被风控」——**全错**。

真相：`http.request()` 返回的已经是 `result` 里的内容，字段直接在顶层。
我在 `_follow_lines` 里写了 `result = data.get("result") or {}`，**多取了一层**，永远是空 dict。

改一行就好了：

```python
result = data if ("follow_list" in data or "follow_cnt" in data) else (data.get("result") or {})
```

### 现在能用的四个工具

| 工具 | 干什么 | 默认行为 |
|---|---|---|
| `follow_user` | 关注某人（传对方 uid） | `dry_run=true` 只预检，要真发必须显式传 `false` |
| `unfollow_user` | 取消关注 | 同上 |
| `list_following` | 我关注了谁；传 `userId` 就查那个人关注了谁 | 只读 |
| `list_followers` | 谁关注了我；传 `userId` 就查那个人的粉丝 | 只读 |

实际输出长这样（带关系数）：

```
条数: 1
用户: ["一品先生｜uid 17427849"]
关系: 关注 1｜粉丝 17｜互关 1
```

### 会丢的风险和堵法

这四个工具是改 `xhh_operator` 的源码加进去的，而它是 uv 装的包，装在：

```
/root/.local/share/uv/tools/xiaoheihe-cli/lib/python3.13/site-packages/xhh_operator/
```

**重装或升级 `xiaoheihe-cli` 会把这个目录覆盖回原版，工具就全没了。**

所以做了备份 + 一键恢复：

```
tools/xhh-patches/
├── service.py.modified      四个方法的实现（在 Operator 类末尾）
├── mcp_server.py.modified   四个工具的注册
└── restore.sh               装回去，自动找目录、先备份、检查语法
```

万一哪天发现工具消失，跑一条命令就行：

```bash
bash tools/xhh-patches/restore.sh
```

脚本会自动找 python 版本目录（不写死 3.13），覆盖前先存 `.bak-时间戳`，装完做 AST 语法检查，最后提示怎么重启 MCP。

### 关注接口的正确参数（记下来省得再试）

- 路径：`POST /bbs/app/profile/follow/user`，取关 `POST /bbs/app/profile/follow/user/cancel`
- **表单只发 `following_id`**（对方 uid），不要发 `follower_id`——这是
  [heybox-lite 的官方 APK 核对文档](https://github.com/huanghao897/heybox-lite/blob/main/docs/OFFICIAL_API_AUDIT.md)写明的
- 报错会直接告诉你缺什么：「both following id and follower id is required」
